# Общие основы

C#-моды и дата-моды используют одинаковые правила для манифеста,
идентификаторов, ресурсов и переводов. Здесь собраны общие настройки;
работу с кодом и JSON-контентом разберём в руководствах по созданию модов.

## Манифест

Файл `module.json` находится в корне папки мода.
Он описывает мод и сообщает игре, что нужно загрузить.

Пример общих полей:

```json
{
  "schemaVersion": 1,
  "id": "example.mod",
  "name": "Example Mod",
  "description": "An example mod for The Adventurer's Era.",
  "authors": ["YourName"],
  "website": "",
  "source": "",
  "icon": "assets/icons/crystal.png",
  "version": "1.0.0",
  "apiVersion": 1,
  "side": "both",
  "dependencies": [],
  "defaultLanguage": "en"
}
```

Для загрузки кода или JSON-контента добавляются соответствующие блоки
`code` или `content`. Их настройка показана в руководствах по
[C#-модам](../csharp-mods/first-mod#настроики-мода) и
[дата-модам](../data-mods/first-data-mod#подключение-контента).

| Поле | Назначение |
| --- | --- |
| `schemaVersion` | Версия формата манифеста. Сейчас `1` |
| `id` | Уникальный идентификатор мода |
| `name` | Отображаемое название. Если не указано, используется ID |
| `description` | Описание мода |
| `authors` | Список авторов |
| `website` | Ссылка на сайт мода |
| `source` | Ссылка на репозиторий исходников |
| `icon` | Путь к PNG-изображению мода |
| `version` | Версия мода в формате `1.0.0` |
| `apiVersion` | Версия API игры. Сейчас `1` |
| `side` | Сторона работы: `client`, `server` или `both` |
| `dependencies` | Обязательные зависимости от других модов |
| `defaultLanguage` | Запасной язык переводов. По умолчанию `en` |

Обязательные поля — `schemaVersion`, `id`, `version`, `apiVersion` и `side`.
Версия мода содержит три числа: например, `1.0.0` или `1.2.3`.
Суффиксы вроде `-beta` сейчас не поддерживаются.

Ссылки `website` и `source` должны начинаться с `https://` или `http://`.
Если поле отсутствует или пустое, соответствующая кнопка в списке модов скрыта.

Для модов, добавляющих предметы и правила выпадения, требуется `side: "both"`.
Подробнее о сторонах работы — в [возможностях и ограничениях](./capabilities-and-limitations#клиентские-и-серверные-моды).

## Идентификаторы и зависимости

### ID мода и предметов

ID мода задаётся в `module.json`, а не именем папки.
Папка `ExampleMod-1.0.0` может содержать мод с ID `example.mod`.

Для ID мода используйте строчные латинские буквы, цифры, `.`, `_` и `-`.
Первый символ должен быть буквой или цифрой, длина — не более 128 символов.
ID `base` зарезервирован для игры.

В описании предмета указывается локальный ID, например `test_crystal`.
Его полный идентификатор включает ID мода:

```text
example.mod:test_crystal
```

Таким образом, `first.mod:copper_ore` и `second.mod:copper_ore` — разные предметы,
даже если оба называются «Медная руда».

В ссылках на контент, например в JSON-правиле выпадения,
используйте полный идентификатор. Префикс `base:` обозначает контент игры,
например таблицу `base:test-mob-loot`.

::: warning Сохранения
ID используются в сохранениях и зависимостях.
Изменение ID опубликованного мода или предмета может сделать старый контент недоступным.
Названия и переводы можно менять отдельно от идентификаторов.
:::

### Зависимости

Если мод требует другой мод, укажите его в `dependencies`:

```json
{
  "dependencies": [
    {
      "id": "other.mod",
      "minVersion": "1.0.0",
      "maxVersion": "2.0.0"
    }
  ]
}
```

Это фрагмент манифеста: добавьте поле в существующий `module.json`.
В примере подходят версии от `1.0.0` включительно до `2.0.0` не включительно.
Границы можно не указывать, если подходит любая версия.

Зависимости загружаются раньше использующего их мода.
Если обязательная зависимость отсутствует, несовместима или не загрузилась,
зависимый мод тоже не загрузится. При отсутствии зависимостей используйте `[]`.

Не устанавливайте одновременно несколько копий одного ID мода,
даже если их версии или имена папок отличаются: такие копии отклоняются загрузчиком.

## Ресурсы и изображения

Пути в манифесте и описаниях контента считаются от корня установленного мода:

```text
ExampleMod-1.0.0/
├── module.json
└── assets/
    └── icons/
        └── crystal.png
```

Путь к изображению в этом случае — `assets/icons/crystal.png`.
Не указывайте абсолютные пути с вашего компьютера и не обращайтесь к файлам вне папки мода.
Используйте `/` в JSON-путях и соблюдайте регистр букв: на Linux он имеет значение.

Изображения предметов и иконка мода используют PNG.
Они могут ссылаться на один файл или на разные.
Файл должен присутствовать в установленной папке, а не только в исходном проекте.

Имена папок с контентом и изображениями можно выбирать самостоятельно,
обновляя ссылки на них. Путь `assets/lang/` для переводов фиксирован.

## Локализация

### Папки языков

Переводы находятся в `assets/lang/<язык>/`:

```text
assets/lang/
├── en/
│   └── items.json
└── ru/
    └── items.json
```

В каждой папке можно использовать один или несколько JSON-файлов.
Например, `items.json`, `mod.json` или `ui.json`.
Названия файлов не влияют на ключи: все тексты одного языка объединяются.
Можно оставить только `items.json` и хранить в нём все переводы.

### Ключи переводов

Файл содержит обычный JSON-объект со строковыми значениями.
Например, `assets/lang/ru/items.json`:

```json
{
  "mod.name": "Пример мода",
  "mod.description": "Добавляет тестовый кристалл.",
  "item.test_crystal.name": "Тестовый кристалл",
  "item.test_crystal.description": "Ресурс, выпадающий с тестового моба."
}
```

| Ключ | Назначение |
| --- | --- |
| `mod.name` | Название мода |
| `mod.description` | Описание мода |
| `item.<локальный ID>.name` | Название предмета |
| `item.<локальный ID>.description` | Описание предмета |

ID мода в ключах предмета не нужен: переводы каждого мода хранятся отдельно.
При смене локального ID предмета обновите и ключи его переводов.

В пределах одного языка ключ не должен повторяться,
в том числе в разных файлах. Повторяющиеся ключи приводят к ошибке загрузки.

### Запасной текст

Игра сначала ищет перевод для выбранного языка,
затем для его общего варианта, если он есть: например, `pt-BR` → `pt`.
Далее используется `defaultLanguage` из манифеста.

Если перевод не найден, для стандартных названий и описаний используется
текст из манифеста, JSON-предмета или C#-класса.
Переводы имеют приоритет над этими текстами, поэтому при переименовании
обновляйте соответствующие языковые файлы.

## Диагностика и частые ошибки

После установки откройте **«Модификации»** в главном меню и проверьте статус мода.
При ошибке загрузки ищите сообщения категории `[Mods]` в журнале игры.

| Проблема | Что проверить |
| --- | --- |
| Мод не найден | Путь `Mods/<папка мода>/module.json`; архив должен быть распакован |
| Файл не найден | Относительный путь, регистр букв и наличие файла в установленном моде |
| Мод не загружается | Корректность JSON, `schemaVersion`, `apiVersion` и обязательных полей |
| Ошибка зависимости | Наличие нужного мода, его версию и ошибки его загрузки |
| Повторяющийся ID | Нет ли второй папки с тем же ID мода |
| Ошибка переводов | Корректность JSON, строковые значения и отсутствие повторяющихся ключей |
| Видно старое название | Переводы имеют приоритет над текстом из кода и JSON |
| Изменения не применились | Обновлена ли установленная копия мода и перезапущена ли игра |

После изменений модов перезапускайте игру.
При обновлении заменяйте старую установленную папку новой.

Когда общие настройки понятны, переходите к
[первому C#-моду](../csharp-mods/first-mod) или
[первому дата-моду](../data-mods/first-data-mod).
