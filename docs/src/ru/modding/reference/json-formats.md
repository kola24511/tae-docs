# Форматы JSON

Справочник описывает текущие форматы предметов и правил выпадения
с `schemaVersion: 1`.
Рабочий пример — [Example Data Mod](https://github.com/kola24511/TAE-example-data-mod).

Манифест и языковые файлы описаны в
[общих основах](../getting-started/common-basics).
Пошаговое руководство — в [первом дата-моде](../data-mods/first-data-mod).

## Подключение файлов

Файлы контента перечисляются в блоке `content` манифеста `module.json`:

```json
{
  "content": {
    "items": ["Data/items.json"],
    "loot": ["Data/loot.json"]
  }
}
```

Это фрагмент манифеста, а не полный файл.
В каждом списке можно указать несколько файлов.
Если предметов или правил выпадения нет, соответствующий список можно не указывать.
При этом блок `content` должен содержать хотя бы один путь к файлу.

Файлы должны существовать внутри установленного мода и иметь расширение `.json`.
Один файл нельзя перечислять в блоке `content` несколько раз.
Для предметов и выпадения требуется `side: "both"`.

## Предметы

### Структура файла

```json
{
  "schemaVersion": 1,
  "items": [
    {
      "id": "blue_crystal",
      "name": "Blue crystal",
      "description": "A resource added by a data mod.",
      "icon": "Icons/crystal.png",
      "maxStack": 99,
      "weight": 1
    }
  ]
}
```

| Поле файла | Обязательное | Значение |
| --- | --- | --- |
| `schemaVersion` | Да | `1` |
| `items` | Да | Непустой массив описаний предметов |

### Поля предмета

| Поле | Тип | Обязательное | Ограничения / значение по умолчанию |
| --- | --- | --- | --- |
| `id` | Строка | Да | Локальный ID; от 1 до 128 символов |
| `name` | Строка | Да | Непустое название, не состоящее только из пробелов; до 128 символов |
| `description` | Строка или `null` | Нет | Не более 4096 символов |
| `icon` | Строка | Да | Относительный путь к существующему PNG внутри мода |
| `maxStack` | Целое число | Нет | От `1` до `9999`; по умолчанию `99` |
| `weight` | Целое число | Нет | От `0` до `10000`; по умолчанию `1` |

В локальном ID разрешены строчные латинские буквы, цифры, `.`, `_` и `-`.
Первый символ — буква или цифра. Префикс мода и `:` в поле `id` не указываются.

Локальные ID должны быть уникальны во всех файлах предметов одного мода.
С ID мода `example.crystal` предмет `blue_crystal` получает полный ID
`example.crystal:blue_crystal`.

`name` требуется даже при наличии перевода:
он используется как запасной текст.

## Правила выпадения

### Структура файла

```json
{
  "schemaVersion": 1,
  "loot": [
    {
      "table": "base:test-mob-loot",
      "item": "example.crystal:blue_crystal",
      "chance": 0.25,
      "minAmount": 1,
      "maxAmount": 3,
      "rarity": "uncommon"
    }
  ]
}
```

| Поле файла | Обязательное | Значение |
| --- | --- | --- |
| `schemaVersion` | Да | `1` |
| `loot` | Да | Непустой массив правил выпадения |

### Поля правила

| Поле | Тип | Обязательное | Ограничения / значение по умолчанию |
| --- | --- | --- | --- |
| `table` | Строка | Да | Полный ID существующей таблицы |
| `item` | Строка | Да | Полный ID существующего предмета |
| `chance` | Число | Да | От `0` до `1` включительно |
| `minAmount` | Целое число | Нет | От `1` до `9999`; по умолчанию `1` |
| `maxAmount` | Целое число | Нет | От `minAmount` до `9999`; по умолчанию `1` |
| `rarity` | Строка | Нет | По умолчанию `"common"` |

Допустимые значения `rarity`:
`common`, `uncommon`, `rare`, `epic`, `legendary`.

`chance: 0.25` означает вероятность 25%, `chance: 1` — 100%.
При успешном выпадении количество выбирается в указанном диапазоне.

Если задаёте `minAmount` больше `1`, задайте и подходящий `maxAmount`:
его значение по умолчанию остаётся равным `1`.

Правила дополняют существующие таблицы выпадения.
Они не создают новых таблиц или мобов.

### Ссылки на контент

`table` и `item` используют формат `mod_id:local_id`.
Каждая часть имеет длину от 1 до 128 символов
и соответствует тем же правилам символов, что и локальный ID предмета.

Допустимые источники:

| Префикс | Источник |
| --- | --- |
| `base:` | Контент игры |
| ID текущего мода | Контент этого мода |
| ID другого мода | Контент объявленной зависимости |

Если ссылаетесь на контент другого мода, добавьте его ID в `dependencies`.
Одной ссылки в правиле недостаточно.
Предмет и таблица должны существовать к моменту регистрации контента.

Пример настройки зависимости — в
[общих основах](../getting-started/common-basics#зависимости).

## Проверка формата

Для файлов предметов и выпадения:

- Используйте имена полей точно как в справочнике: `maxStack`, а не `MaxStack`.
- Не добавляйте неизвестные поля.
- Не повторяйте ключи внутри одного JSON-объекта.
- Указывайте числа без кавычек: `0.25`, а не `"0.25"`.
- Размер каждого файла контента не должен превышать 1 МиБ.
- Массивы `items` и `loot` в объявленных файлах должны быть непустыми.

Неизвестные поля и повторяющиеся ключи отклоняются загрузчиком.
Числовые диапазоны, наличие изображений и ссылки на контент проверяются при загрузке.

Если правила выпадения не нужны, не объявляйте файл лута в манифесте,
вместо добавления файла с пустым массивом `loot`.

## JSON Schema

SDK игры содержит схемы для редакторов с поддержкой JSON Schema:

| Схема | Файл |
| --- | --- |
| `Schemas/module.schema.json` | Манифест `module.json` |
| `Schemas/items.schema.json` | Описания предметов |
| `Schemas/loot.schema.json` | Правила выпадения |
| `Schemas/lang.schema.json` | Языковые файлы |

Схемы можно подключить через настройки редактора.
В манифест и файлы контента не добавляйте служебное поле `$schema`.

JSON Schema помогает проверять структуру и значения,
но не проверяет наличие PNG, существование игровых таблиц,
ссылки на установленные моды и связь `minAmount` с `maxAmount`.
После изменения контента проверяйте загрузку мода в игре.

Причины ошибок загрузки собраны в
[общих основах](../getting-started/common-basics#диагностика-и-частые-ошибки).
